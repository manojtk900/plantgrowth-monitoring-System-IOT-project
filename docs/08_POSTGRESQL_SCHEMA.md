# PostgreSQL Production Data Model Specification

**Project:** IoT-Based Plant Growth & Environmental Monitoring System  
**Engine:** PostgreSQL 15 / 16 (Render Managed PostgreSQL & Supabase Compatible)  
**Encoding:** UTF-8  
**Timezone:** UTC / Coordinated Universal Time  

---

## 1. Schema Architecture Overview

The PostgreSQL production data model preserves 100% logical parity with the existing SQLite schema while enhancing relational integrity, indexing performance, and data validation constraints.

```
┌────────────────────────────────────────────────────────┐
│                   sensor_readings                      │
├──────────────────────────┬─────────────────────────────┤
│ id                       │ BIGINT PRIMARY KEY GENERATED│
│ device_id                │ VARCHAR(64) NOT NULL        │
│ moisture_raw             │ DOUBLE PRECISION            │
│ moisture_percent         │ DOUBLE PRECISION            │
│ temperature_c            │ DOUBLE PRECISION            │
│ distance_cm              │ DOUBLE PRECISION            │
│ plant_height_cm          │ DOUBLE PRECISION            │
│ status                   │ VARCHAR(32) NOT NULL        │
│ created_at               │ TIMESTAMPTZ NOT NULL        │
└──────────────────────────┴─────────────────────────────┘
                             ▲
                             │ (Configures telemetry bounds)
┌────────────────────────────┴───────────────────────────┐
│                   system_settings                      │
├──────────────────────────┬─────────────────────────────┤
│ key                      │ VARCHAR(64) PRIMARY KEY     │
│ value                    │ TEXT NOT NULL               │
│ updated_at               │ TIMESTAMPTZ NOT NULL        │
└──────────────────────────┴─────────────────────────────┘
```

## 2. Table DDL Specifications

### 2.1 Table: `sensor_readings`
Stores raw and calibrated telemetry frames received from edge microcontrollers (`ESP32_003`).

```sql
CREATE TABLE IF NOT EXISTS sensor_readings (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    device_id VARCHAR(64) NOT NULL DEFAULT 'ESP32_003',
    moisture_raw DOUBLE PRECISION,
    moisture_percent DOUBLE PRECISION,
    temperature_c DOUBLE PRECISION,
    distance_cm DOUBLE PRECISION,
    plant_height_cm DOUBLE PRECISION,
    status VARCHAR(32) NOT NULL DEFAULT 'OK',
    created_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,

    -- Integrity Constraints
    CONSTRAINT chk_moisture_raw CHECK (moisture_raw IS NULL OR (moisture_raw >= 0.0 AND moisture_raw <= 4095.0)),
    CONSTRAINT chk_moisture_pct CHECK (moisture_percent IS NULL OR (moisture_percent >= 0.0 AND moisture_percent <= 100.0)),
    CONSTRAINT chk_temperature_c CHECK (temperature_c IS NULL OR (temperature_c >= -40.0 AND temperature_c <= 85.0)),
    CONSTRAINT chk_distance_cm CHECK (distance_cm IS NULL OR distance_cm >= 0.0)
);

-- Performance Indexes for Time-Series Aggregations and Filtering
CREATE INDEX IF NOT EXISTS idx_sensor_readings_created_at 
    ON sensor_readings (created_at DESC);

CREATE INDEX IF NOT EXISTS idx_sensor_readings_device_created 
    ON sensor_readings (device_id, created_at DESC);

CREATE INDEX IF NOT EXISTS idx_sensor_readings_status 
    ON sensor_readings (status);
```

### 2.2 Table: `system_settings`
Stores centralized calibration constants and system thresholds, decoupling hardware from configuration.

```sql
CREATE TABLE IF NOT EXISTS system_settings (
    key VARCHAR(64) PRIMARY KEY,
    value TEXT NOT NULL,
    updated_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP
);

-- Initial Factory Calibration Seeds
INSERT INTO system_settings (key, value, updated_at) VALUES
    ('dry_raw', '3326.0', CURRENT_TIMESTAMP),
    ('wet_raw', '1520.0', CURRENT_TIMESTAMP),
    ('sensor_mount_height_cm', '30.0', CURRENT_TIMESTAMP),
    ('drying_risk_temp_threshold', '30.0', CURRENT_TIMESTAMP),
    ('low_moisture_threshold', '25.0', CURRENT_TIMESTAMP),
    ('device_id', 'ESP32_003', CURRENT_TIMESTAMP)
ON CONFLICT (key) DO NOTHING;
```

## 3. Data Type Mapping (SQLite vs. PostgreSQL)

| Column | SQLite Type | PostgreSQL Type | Migration Rationale |
| :--- | :--- | :--- | :--- |
| `id` | `INTEGER PRIMARY KEY AUTOINCREMENT` | `BIGINT GENERATED BY DEFAULT AS IDENTITY` | Allows explicit insertion of historical IDs (1..89) during migration while auto-generating future IDs. |
| `device_id` | `TEXT` | `VARCHAR(64)` | Bounded string length; indexed for device filtering. |
| `moisture_raw` | `REAL` | `DOUBLE PRECISION` | 64-bit IEEE float preserving exact ADC precision. |
| `moisture_percent`| `REAL` | `DOUBLE PRECISION` | Exact decimal precision for Relative Soil Moisture Index. |
| `temperature_c` | `REAL` | `DOUBLE PRECISION` | Preserves DS18B20 12-bit temperature resolution ($0.0625^\circ\text{C}$). |
| `distance_cm` | `REAL` | `DOUBLE PRECISION` | Preserves ultrasonic flight-time precision. |
| `plant_height_cm` | `REAL` | `DOUBLE PRECISION` | Calculated canopy height from baseline. |
| `status` | `TEXT` | `VARCHAR(32)` | Bounded status indicator string (`OK`, `FAULT`). |
| `created_at` | `TEXT` (ISO 8601) | `TIMESTAMPTZ` | Standardized UTC timestamp with timezone offset support. |

## 4. Sequence Synchronization Protocol

During migration from SQLite, records are inserted with their original sequential IDs (`1` to `89`). In PostgreSQL, using `GENERATED BY DEFAULT AS IDENTITY` permits explicit ID insertion, but requires advancing the sequence afterward:

```sql
SELECT setval(
    pg_get_serial_sequence('sensor_readings', 'id'),
    COALESCE((SELECT MAX(id) FROM sensor_readings), 1) + 1,
    false
);
```

This guarantees that the very next telemetry frame from `ESP32_003` receives `id = 90` without primary key collisions.
